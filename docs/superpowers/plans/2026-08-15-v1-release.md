# `hy-text` v1.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pass every documented release gate, including three independent scoring passes, and publish the first stable GitHub Release `v1.0.0` from `master`.

**Architecture:** Keep the runtime corpus Markdown-only and network-free. Add deterministic Python release tooling around blind agent outputs, separate expert gold from blinded inputs, validate five packaging formats in isolated temporary homes, and publish only after local checks plus the three-OS GitHub Actions run succeed.

**Tech Stack:** Markdown, JSON, Python 3.12 standard library, `unittest`, Git, GitHub Actions, GitHub CLI.

## Global Constraints

- Support only modern Eastern Armenian and the reformed orthography used in the Republic of Armenia.
- Never create a branch whose name begins with `codex`; the release branch is `release/v1.0.0` and the default branch is `master`.
- Use spaced en dashes in prose and never introduce U+2014.
- Preserve code, commands, URLs, foreign-language spans, third-party quotations, and official protected spellings verbatim.
- Runtime skills perform no network requests and never write to user-authored source files.
- Keep the public scoring weights, caps, labels, and five dimensions unchanged.
- Do not alter expert scores to make calibration pass and do not weaken the `±0.7` total or `±1.0` dimension thresholds.
- Do not create `v1.0.0` until every local gate and the Windows, macOS, and Linux CI jobs succeed on the exact release commit.
